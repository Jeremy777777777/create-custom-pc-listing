## Reuse before acquisition or generation

1. Read `assets/branding/library/asset-registry.json` and verify the selected original's hash. Reuse an existing applicable master first.
2. If absent, obtain the actual file from an observed official brand/media/partner page or approved seller source. Keep native SVG/vector and high-resolution transparent PNG where provided. Preserve original bytes; never replace them with a model-drawn approximation.
3. Save under a stable descriptive asset ID and register source page, actual download URL, date, version/family/tier/edition, MIME, byte size, SHA256, authorization basis, light/dark suitability and intended uses. Retain an access-failed/partner-login record when appropriate; it is not a downloaded usable asset. Do not save signed URLs, account tokens or credentials in shared metadata.
4. A derivative records its parent hash, conversion/crop method and output hash. Proportion-preserving resize/rasterization is allowed; no recoloring, stretching, altered numbers, generated lettering or substituting an adjacent processor tier. Keep built-in white space unless a documented alpha-bound crop is needed for layout.
5. Render the original asset as a frozen layer after scene generation. Record asset ID/hash and measured placement in the product recipe. Do not ask the image model to redraw it. Verify the final visible mark against the original at full size and mobile size.

Run `python scripts/brand_assets.py verify --repo .` to check registered bytes and paths. Use `select --context <verified-brand-context.json>` to identify compatible registered masters. The selector is an applicability aid, never evidence that supplied context is true.
